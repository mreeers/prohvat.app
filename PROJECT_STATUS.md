# Статус проекта "Prohvat"

## 🚀 Что уже реализовано

### Backend (ASP.NET Core Web API)
* **Архитектура:** Построена на CQRS с использованием MediatR, Entity Framework Core (PostgreSQL) в качестве ORM.
* **Аутентификация и авторизация:** Реализована на базе JWT-токенов. Настроены кастомные claims (например, `username` и `sub`) для удобной работы на клиенте.
* **Покатушки (Rides):**
  * Создание покатушек с указанием гео-координат.
  * Получение покатушек в заданной области карты (Bounding Box).
  * Возможность присоединиться и покинуть покатушку.
  * Публичный просмотр списка покатушек на карте.
* **Споты (Spots):**
  * Добавление интересных мест на карту.
  * Публичное отображение спотов.
* **Бортжурналы (Vehicles):**
  * Добавление транспортных средств (мотоциклов и др.).
  * Ведение логов обслуживания/поездок с привязкой к ТС.
  * Публичный просмотр профиля ТС и истории логов (без необходимости авторизации).
  * Редактирование и добавление логов доступно только владельцу.
* **Профили пользователей:**
  * Просмотр профиля по уникальному username.
  * Отображение связанной информации (добавленные ТС).
  * Загрузка аватарок и медиафайлов через **MinIO (S3-совместимое хранилище)**.
* **Социальное взаимодействие (Social Core):**
  * Комментарии к бортжурналам, покатушкам и спотам.
  * Система лайков (оценок).
  * Оставление отзывов с рейтингом.
* **Real-time (SignalR):**
  * Живой приватный чат внутри покатушек (только для участников).
  * Мгновенные In-App уведомления о новых лайках и комментариях.

### Frontend (Vue 3 + Vite)
* **Стек:** Vue 3 (Composition API), Pinia (стейт-менеджмент), Vue Router.
* **Карта:** Интеграция с библиотекой Leaflet для отображения интерактивной карты, покатушек и спотов.
* **UX/UI (Редизайн в стиле VK 2015):** 
  * Глобальный редизайн с сохранением темной премиальной темы.
  * Фиксированная верхняя шапка и классическое левое меню (Моя страница, Новости, Друзья, Карта, Споты, Гараж, Настройки).
  * Разделение контента на тематические View для упрощения навигации.
* **Социальные функции (Фронтенд):**
  * Управление друзьями (заявки, удаление) прямо из профиля.
  * Выделенная страница "Мои друзья" (разделение на активных друзей и заявки).

## 🛠 Предложения по оптимизации для Production

Для подготовки проекта к высоким нагрузкам и развертыванию в Production, рекомендуется внедрить следующие технологии и подходы:

### 1. Кэширование (Redis)
* **Зачем:** Для снижения нагрузки на базу данных PostgreSQL и ускорения отдачи данных.
* **Что кэшировать:** 
  * Справочники (список регионов, категорий транспорта).
  * Активные покатушки в популярных регионах.
  * Сессии пользователей и токены (если используется stateful подход или для отзывов токенов/refresh tokens).
  * Данные профилей, которые редко меняются.

### 2. Асинхронная обработка и очереди (RabbitMQ / Kafka)
* **Зачем:** Для развязки компонентов системы, повышения отказоустойчивости и асинхронного выполнения тяжелых задач.
* **Где применить:**
  * Отправка Email / Push-уведомлений (например, "В вашем регионе создана новая покатушка").
  * Асинхронная обработка загружаемых изображений (ресайз, компрессия, создание превью для бортжурналов).
  * Сбор и агрегация аналитики (кто куда кликал, какие споты самые популярные).

### 3. Real-time взаимодействие (SignalR / WebSockets) - **✅ ЧАСТИЧНО РЕАЛИЗОВАНО (Чат + Уведомления)**
* **Что осталось:**
  * Трансляция геолокации участников в реальном времени (Live Tracking) на карте во время активной покатушки.

### 4. Хранение медиафайлов (MinIO / AWS S3) - **✅ РЕАЛИЗОВАНО**
* Интегрирован `MinioFileService`. Все аватарки и фото теперь надежно сохраняются в отдельном бакете S3, что разгружает основной сервер.

### 5. Поиск и фильтрация (Elasticsearch)
* **Зачем:** Если появится сложный поиск по тексту (поиск пользователей, полнотекстовый поиск по бортжурналам, комментариям, тегам).
* **Как реализовать:** Синхронизация данных из PostgreSQL в Elasticsearch через RabbitMQ или напрямую (Debezium/CDC).

### 6. Инфраструктура и DevOps (Docker, CI/CD)
* **Контейнеризация:** Упаковка Frontend и Backend в Docker-образы. Настройка `docker-compose.yml` для локального запуска полного стека (PostgreSQL, Redis, RabbitMQ, API, Web).
* **CI/CD:** Настройка GitHub Actions (или GitLab CI) для автоматического прогона тестов, сборки образов и деплоя на сервер (или в Kubernetes).
* **Reverse Proxy:** Использование Nginx или Traefik для терминации SSL (HTTPS), балансировки нагрузки и маршрутизации между фронтендом и бэкендом.

### 7. Мониторинг и логирование (Prometheus + Grafana, ELK / Seq)
* Настроить сбор метрик (.NET EventCounters, Prometheus endpoint) для отслеживания нагрузки (CPU, Memory, GC) и RPS.
* Централизованный сбор логов (например, с использованием Serilog + Seq или Elastic Stack), чтобы быстро находить ошибки в проде.
